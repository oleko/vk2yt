# vk2yt — автоперенос архива видео из сообщества VK на YouTube (и RuTube)

Скрипт постепенно, по несколько роликов в день, переносит архив видео сообщества
ВКонтакте на YouTube-канал — с оригинальными названиями и описаниями. Опционально
умеет доливать на RuTube то, что не подхватил их встроенный импорт с YouTube.

Задача, под которую он написан: в сообществе накопились тысячи роликов, их надо
перенести не «одним махом» (упрётесь в квоту YouTube и место на диске), а ровным
потоком, ничего не потеряв и не создав дублей.

## Что умеет

- **Разовая инвентаризация архива.** Забирает весь список видео сообщества через
  VK API и строит `plan.json` — фиксированный порядок выгрузки от старых к новым с
  разбивкой по дням и прогнозом даты финиша.
- **Ежедневная порция.** По cron берёт следующие N роликов, скачивает через
  `yt-dlp`, заливает на YouTube (resumable upload) и **сразу удаляет файл** — на
  диске одновременно лежит не больше одного ролика.
- **Дедупликация.** Перед каждым прогоном сверяет план с тем, что уже есть на
  YouTube и RuTube, и помечает совпадения как залитые. Без этого скрипт повторно
  зальёт ролики, которые вы когда-то выкладывали руками.
- **Устойчивость к сбоям.** Состояние каждого ролика пишется в `processed.json`
  сразу после каждого шага: падение посреди прогона ничего не теряет и не приводит
  к повторной заливке. Ошибки повторяются до `MAX_RETRIES` раз.
- **Веб-дашборд.** Прогресс, ссылки на залитые ролики, хвост лога, кнопка
  «Запустить сейчас», OAuth-авторизация YouTube через браузер.

## Как это работает

```
VK API (video.get)  ->  plan.json  ->  [ежедневный прогон]  ->  YouTube
                                              |                    |
                                         yt-dlp скачал        (опц.) RuTube
                                         залил, удалил
```

1. `--plan` собирает весь архив сообщества (постранично, по 100 записей) и
   сохраняет порядок выгрузки. Видеофайлы при этом **не скачиваются** — только
   метаданные.
2. `--reconcile` сверяет план с YouTube и RuTube по названиям и отмечает то, что
   уже опубликовано.
3. Обычный запуск берёт первые `DAILY_LIMIT` необработанных роликов по порядку
   плана. Если день пропущен (сервер лежал), очередь просто продолжится с того же
   места — план задаёт порядок, а не жёсткие даты.
4. Когда архив закончится, повторный `--plan` дописывает новые ролики в конец.

### Про RuTube

У RuTube есть собственный импорт с YouTube-канала: подключаете канал в кабинете, и
новые ролики он подтягивает сам. Прямая заливка в этом скрипте нужна только как
дозаливка того, что импорт пропустил, поэтому она:

- сверяется с тем, что уже есть на канале RuTube, и не трогает найденное;
- ждёт `RUTUBE_IMPORT_GRACE_H` часов после заливки на YouTube — вдруг импорт ещё
  подхватит ролик сам;
- заливает **по ссылке**: RuTube не принимает файл загрузкой, ему дают публичный
  URL, и он приходит за файлом сам. Поэтому файл на время кладётся в каталог
  `ingest/`, раздаётся через nginx и удаляется после подтверждения.

Если RuTube вам не нужен — оставьте `RUTUBE_ENABLED=0`, всё остальное работает.

## Требования

- Python 3.10+, `ffmpeg`, `yt-dlp`
- Сервер с публичным доменом и HTTPS — нужен для OAuth-редиректа Google, а для
  RuTube ещё и для раздачи файла
- Аккаунт Google с доступом к нужному YouTube-каналу
- Права администратора сообщества VK (или сервисный ключ приложения)

## Установка

```bash
git clone https://github.com/<вы>/vk2yt.git /opt/vk2yt
cd /opt/vk2yt

sudo apt update && sudo apt install -y python3-venv ffmpeg
python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt

cp .env.example .env && chmod 600 .env
```

Дальше заполняем `.env` — по шагам ниже.

### 1. Доступ к VK

Методу `video.get` нужно право **video**. Подойдёт любой из вариантов:

- **Ключ сообщества** (если вы администратор): Управление → Работа с API →
  Создать ключ → право **Видео**. Обязательно включите **«Доступ в любое время»**,
  иначе VK заблокирует токен при обращении с IP сервера.
- **Сервисный ключ Standalone-приложения** — подставляется как `access_token`,
  отдельной авторизации не требует.

Заполните `VK_TOKEN` и `VK_GROUP_ID` (числовой ID сообщества без минуса).

Если часть роликов закрыта настройками приватности, `yt-dlp` не скачает их
анонимно — экспортируйте cookies браузера и укажите путь в `VK_COOKIES_FILE`.

### 2. Доступ к YouTube Data API

1. [Google Cloud Console](https://console.cloud.google.com) → создать проект.
2. Включить **YouTube Data API v3**.
3. **OAuth consent screen** → тип External, добавить свой аккаунт в Test users.
4. **Credentials → Create OAuth client ID → Web application**.
5. В **Authorized redirect URIs** добавить `https://ваш-домен/oauth2callback`.
6. Скачать JSON, положить рядом со скриптами как `client_secret.json`.
7. В `.env` указать тот же `YOUTUBE_REDIRECT_URI`.

Авторизация проходит через дашборд: откройте `https://ваш-домен/oauth2start`,
войдите аккаунтом, который управляет каналом, и разрешите доступ. Токен
сохранится в `token.json`, дальше обновляется сам.

> Канал определяется тем, каким аккаунтом вы авторизовались. Если у аккаунта
> несколько каналов, выберите нужный на экране согласия. `YOUTUBE_CHANNEL_ID`
> в `.env` — страховка: скрипт откажется работать, если авторизовались не туда.

### 3. Доступ к RuTube (опционально)

OAuth у RuTube нет — только логин и пароль обычного аккаунта, они идут в `.env`.
Аккаунт должен быть с **подтверждённым e-mail**, иначе API откажет в загрузке.

Если аккаунт редакторский (роликами владеет канал, а не вы лично), укажите
`RUTUBE_CHANNEL_ID` — ID из ссылки `rutube.ru/channel/<ID>/`. По нему берётся
инвентарь канала и к нему же привязывается заливка.

### 4. nginx

```nginx
server {
    listen 443 ssl;
    server_name ваш-домен;
    # ssl_certificate ... — например, через certbot --nginx

    # Только если используете прямую заливку на RuTube:
    location /_ingest/ {
        alias /opt/vk2yt/ingest/;
        autoindex off;
    }

    location / {
        proxy_pass http://127.0.0.1:8766;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
    }
}
```

Заголовок `X-Forwarded-Proto` обязателен: без него OAuth-редирект соберётся с
`http://` и Google отклонит его как несовпадающий.

### 5. Дашборд как сервис

```ini
# /etc/systemd/system/vk2yt-dash.service
[Unit]
Description=VK2YT Dashboard
After=network.target

[Service]
WorkingDirectory=/opt/vk2yt
EnvironmentFile=/opt/vk2yt/.env
ExecStart=/opt/vk2yt/venv/bin/python3 dashboard.py
Restart=on-failure
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now vk2yt-dash
```

Дашборд слушает `127.0.0.1` — наружу его отдаёт только nginx.

## Первый запуск

```bash
cd /opt/vk2yt && . venv/bin/activate
export $(cat .env | grep -v '^#' | xargs)

python3 vk_to_youtube_sync.py --check      # проверить все доступы
python3 vk_to_youtube_sync.py --plan       # собрать план (метаданные, без видео)
python3 vk_to_youtube_sync.py --reconcile  # отметить то, что уже опубликовано
python3 vk_to_youtube_sync.py --dry-run    # посмотреть порцию, ничего не делая
python3 vk_to_youtube_sync.py --limit 1    # боевой тест на одном ролике
```

**`--reconcile` перед первым прогоном обязателен**, если на канале уже что-то
лежит: иначе скрипт зальёт эти ролики повторно.

## Расписание

```cron
0 13 * * * cd /opt/vk2yt && export $(cat .env | grep -v '^#' | xargs) && \
  flock -n running.lock nice -n 10 ionice -c2 -n7 \
  /opt/vk2yt/venv/bin/python3 vk_to_youtube_sync.py >> vk2yt.log 2>&1
```

`flock` не даёт прогонам наложиться друг на друга и на ручной запуск из
дашборда, `nice`/`ionice` — не мешать остальному на сервере. Время выбирайте
такое, когда сервер посвободнее.

Когда в сообществе появляются новые ролики, периодически перестраивайте план:
`python3 vk_to_youtube_sync.py --plan` (уже обработанное не трогается).

## Команды

| Команда | Что делает |
|---|---|
| `--check` | Проверяет VK, YouTube, RuTube и раздачу `ingest/` наружу |
| `--plan` | Собирает/обновляет `plan.json` |
| `--reconcile` | Сверяет план с YouTube и RuTube, метит уже опубликованное |
| `--dry-run` | Показывает ближайшую порцию и куда пойдёт каждый ролик |
| `--limit N` | Ограничить число роликов за прогон |
| `--only youtube\|rutube` | Работать только с одной площадкой |

## Структура

| Файл | Назначение |
|---|---|
| `vk_to_youtube_sync.py` | Оркестратор и CLI |
| `config.py` | Чтение `.env`, пути, значения по умолчанию |
| `vk_source.py` | VK API и скачивание через `yt-dlp` |
| `plan_store.py` | `plan.json`: порядок выгрузки и сводка |
| `registry.py` | `processed.json`: состояние по каждому ролику |
| `youtube_target.py` | OAuth и resumable upload |
| `rutube_target.py` | Клиент RuTube и раздача файла через `ingest/` |
| `dedup.py` | Инвентари площадок и сверка |
| `dashboard.py` | Flask-дашборд |

Рабочие файлы (`plan.json`, `processed.json`, `.env`, токены) в репозиторий не
попадают — см. `.gitignore`.

## Грабли, на которые мы наступили

Собрано по ходу реальной эксплуатации — возможно, сэкономит вам время:

- **VK `video.get` отдаёт максимум 100 записей за вызов**, хотя документация
  обещает 200. Промежуточные страницы иногда возвращают на одну запись меньше
  запрошенного, так что «страница неполная — значит конец» не работает:
  ориентируйтесь на `count` из ответа.
- **VK отдаёт ссылки на видео в домене `vkvideo.ru`** (поле `share_url`), а не
  `vk.com`. Берите ссылку из ответа API, не собирайте руками.
- **RuTube отвечает `403` на дефолтный User-Agent библиотеки `requests`.**
  Нужен браузерный `User-Agent`, иначе не работает вообще ничего.
- **RuTube требует подтверждённый e-mail** для загрузки по API, иначе `403`
  с текстом «Подтвердите e-mail, чтобы загружать видео».
- **У редакторского аккаунта RuTube `/api/video/person/` возвращает пусто** —
  своих роликов у него нет. Инвентарь канала берётся по `RUTUBE_CHANNEL_ID`.
- **Квота YouTube: 10 000 юнитов в сутки, заливка стоит 1 600.** Это ровно 6
  роликов в день, запаса на повторы нет. Ошибка `quotaExceeded` останавливает
  прогон целиком — остаток суток всё равно бесполезен.
- **Сверка идёт по названиям** — другого общего идентификатора между VK, YouTube
  и RuTube нет. Если у двух роликов одинаковые названия, скрипт не трогает их и
  пишет предупреждение: лучше пропустить, чем создать дубль.

## Ограничения

- Заливайте только тот контент, права на который принадлежат вам.
- Лимит размера файла на RuTube — 2 ГБ.
- Пока файл лежит в `ingest/`, он доступен по неугадываемой публичной ссылке.
- Пароль RuTube хранится в `.env` открытым текстом — у их API нет OAuth.
